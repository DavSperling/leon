### 1.2 Who may see what, redirects (nothing in the shell may change these)

- `src/proxy.ts` (L8-14): only `matcher: '/'`. For GET/HEAD on `/` without a Better Auth session cookie (`getSessionCookie`), it rewrites to `/accueil` (public home, `(site)`), with `Cache-Control: private, no-store, max-age=0`. With a cookie, `NextResponse.next()`; a stale cookie is then caught by `requireUserContext`. POST on `/` (server actions of the app) passes through. There is no other global guard; every other route protects itself.
- `requireUserContext()` (`src/server/auth/session.ts` L48-52): no session -> `redirect('/connexion')`; session but no organisation -> `redirect('/bienvenue')`.
- `(app)/layout.tsx`: a member whose `onboardedAt` is null -> `/bienvenue`; a member row not found -> app is shown.
- `(app)/admin/page.tsx` (14 lines): `getSession()`; no session or `!isAdmin(email)` (emails of `LEON_ADMINS`, `src/server/admin/stats.ts` L70-72) -> `notFound()` (a missing page, not a refusal). Renders `AdminDashboard` (`src/components/verre/admin/index.tsx`). IMPORTANT: no link to `/admin` exists anywhere in the UI (grep found none). It is URL-only. The shell has NO admin entry.
- `(onboarding)/layout.tsx` uses `StandaloneShell` + `Brand` (outside the app shell); `(auth)` screens use `components/verre/auth/standalone-card.tsx` (imports `Brand`); `not-found.tsx` uses `StandaloneShell`.
- Other consumers of shell pieces that the port must not break: `components/site/site-shell.tsx` (imports `Aurora`, `ThinkingProvider`), `site-header.tsx`, `site-footer.tsx`, `parts.tsx`, `auth-aside.tsx`, `fx/logo-sphere.tsx`, `home/signal.tsx` (import `Brand`/`Logo`); `recherche/search-bar.tsx`, `discussion/discussion-thread.tsx`, `discussion/new-discussion-form.tsx` (use `useThinking`); `src/test/contracts/guides-docs.test.ts` (imports `NAV`, see risks).

### 1.4 Shell behaviours (all must survive)

Keys (app-shell.tsx L50-74):
- `Cmd/Ctrl+K`: `preventDefault`; if `focusSearchBar()` succeeds (no dialog open and `#barre-de-recherche` input exists, i.e. on `/` Search home; `SEARCH_INPUT_ID` in `src/components/search/url-state.ts` L10) it focuses and selects that input, else toggles the palette.

- Layer guard: `layerOpen()` = any `[role=dialog], [role=alertdialog]` in the DOM.
Rail (rail.ts): states `deplie` 248px / `replie` 64px; choice stored in `localStorage['leon-rail']` (`deplie`|`replie`), without a choice it follows the window (expanded from 1280px, folded below). Server renders expanded. Storage may throw (try/catch, session-only).
Route change: `<main>` scrolls to top and takes focus (`preventScroll`) unless a layer is open.
Page width: `max-w-[1240px]`, `1424px` when folded, width frozen through `--page-w` for 240ms during the fold (template.tsx reads it).
Skip link: first focusable, to `#contenu`.
Reduced motion: `ThinkingProvider` sets `MotionGlobalConfig.skipAnimations`.

## 7. Risks

1. Hard-coded rail widths: 248 / 64 appear in `sidebar.tsx` L139, `app-shell.tsx` L85, `command-palette.tsx` L267-268 (offsets 27px and 119px derive from them) and `template.tsx` via `--page-w`. Changing to 256/60 without updating all four breaks the fold animation or the palette centring. Anchoring the command bar to the ask bar removes the palette offsets.
2. Scroll container: today `<main>` is the scroller inside a rounded panel and `position: fixed` surfaces rely on `<main>` not having `backdrop-filter` (comment at app-shell.tsx L135-136). Moving to window scroll changes: route-change `scrollTo`, `Sheet`/`Dialog` scroll lock, `scroll-padding-top` for anchors (prototype `html { scroll-padding-top: 96px }`), and any child using `main` scroll (grep `getElementById('contenu')` consumers and `src/lib/verre/scroll.ts`). Verify every screen that scrolls programmatically.
3. Stale layout data: Recent, connection flag, people count and stale channels are computed in the layout and do not refresh on client navigation. Add `revalidatePath('/', 'layout')` (or targeted tags) to `newDiscussionAction`, `continueInDiscussionAction`, `deleteDiscussionAction`, the connection actions (`(app)/connexions/actions.ts`), and the member invite/remove actions; or fetch the sidebar data through a client-refreshed path. Otherwise the flag stays after a repair and a new discussion does not appear in Recent. Note `layout.test.ts` and each actions test will need their `next/cache` mock.
4. Layout cost: adding `listDiscussions`, `listConnections` (uses `withTenant`, decrypts nothing but joins users), `listMembers` to every layout render multiplies DB reads on each full navigation. `listConnections` is heavy (all columns, joins). Prefer a lean query (`select provider, status, creatorLeft, canManage` only) and a count query for members; keep them in the existing `Promise.all`. The audit history notes DB connection limits (Supabase pool errors); do not add three more connections per request.
5. Privacy: a palette feed must respect visibility (private documents are owner-only, former members have empty email, `members.job` is hidden for plain members). Do not pass the full catalogs from the layout to the client; use a server action with the same `ctx` filters as the screens. `connections.config` strips `depots_confirmes` for non-creators: do not reuse raw rows in the layout.
6. Tailwind vs prototype CSS: the real app is Tailwind 4 with tokens in `src/app/globals.css` (utilities like `shell:`, `max-shell:`, `bg-glass`, `rounded-box`, `shadow-hi`, `glass-float`, `layer-dialog`, `signal-line`); the prototype is plain CSS with tokens `--desk`, `--sheet`, `--ink`, `--line`, `--d1..d3`, `--c1..c4`, `--r-s/m/l`, `--sh-1..3`. Builders must port token values into the Tailwind theme once (single owner, probably the tokens/foundation builder) before restyling components, or the shell will fork the palette.
