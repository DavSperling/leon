## 1. Ce qui domine en octobre 2026, et pourquoi

**TypeScript est devenu la langue des produits codés avec des agents.** GitHub Octoverse 2025 : TypeScript est passé n°1 sur GitHub en août 2025 (+66,6 % de contributeurs en un an, devant Python +48,8 %), avec deux causes citées : les frameworks scaffoldent en TS par défaut, et le typage rattrape les erreurs des LLM (« 94 % des erreurs de compilation du code généré sont des erreurs de type »). Stack Overflow 2026 : JavaScript 62 %, Python 58 %, TypeScript 43,8 % ; PostgreSQL 57,9 % ; 74,6 % des devs utilisant un LLM citent Anthropic. Python reste roi quand le produit *est* du ML (Mem0 : 4,7 Mo de Python, Cognee : 17,7 Mo). Les produits « plateforme » comparables à Leon sont en TypeScript : Dust (62,7 Mo de TS, 8,4 Mo de Rust pour le cœur vectoriel, Temporal, Next.js, Qdrant/Elasticsearch), Supermemory (TS, 31 k étoiles), Nango (TS), Trigger.dev (TS). Claude Code lui-même est en TypeScript, et Anthropic a racheté Bun le 2 décembre 2025 pour en faire « l'infrastructure de Claude Code et du Agent SDK ».

**Le reste du socle est stable.** State of JS 2025 : React 83,6 % d'usage, Next.js 58,6 % (satisfaction 55 % seulement, mais sans rival en usage), Express 79,9 %, Hono en S-tier (95 % de satisfaction), Vite 98 %, Bun 91 % ; pnpm nettement premier des monorepos (3 940 répondants contre Turborepo 1 718 et Nx 1 682) ; hébergement AWS 5 099, Vercel 4 703, Cloudflare 3 041, Fly.io 249. Stack Overflow 2025 (le 2026 ne détaille pas les frameworks) : Node 48,7 %, React 44,7 %, Next.js 20,8 %, Express 19,9 %, FastAPI 14,8 %, Django 12,6 % ; AWS 43,3 %, Cloudflare 20,1 %, Vercel 10,6 %.

**Téléchargements npm, dernier mois (12/10/2026)** : next 278 M ; hono 304 M (gonflé par les outils qui l'embarquent) ; express 620 M ; fastify 64 M ; **drizzle-orm 112 M contre @prisma/client 76 M** (kysely 82 M) ; **better-auth 44 M contre next-auth 28 M, @workos-inc/node 14 M, @clerk/nextjs 11 M** ; bullmq 40 M, @temporalio/client 18 M, inngest 10 M, pg-boss 9,7 M, @trigger.dev/sdk 4,7 M, graphile-worker 2,9 M ; @modelcontextprotocol/sdk 267 M ; @radix-ui/react-dialog 331 M contre @base-ui-components/react 2 M ; tailwindcss 593 M ; turbo 121 M contre nx 45 M ; @trpc/server 24 M, @orpc/server 6,6 M ; @anthropic-ai/sdk 190 M, Vercel AI SDK (`ai`) 123 M. Côté PyPI : fastapi 382 M, sqlalchemy 330 M, mcp 235 M, anthropic 150 M.

**Versions courantes** : Next.js 16.4 (6 oct. 2026 ; Next 16 du 21 oct. 2025 a rendu Turbopack par défaut, Cache Components, React 19.3) ; Hono 4.13 ; Drizzle 0.45 ; Prisma ORM 8 annoncé le 12 oct. 2026 (JSON typé, polymorphisme, pgvector, migrations TS) ; Better Auth 1.7.7 (30 k étoiles, 11,8 M/semaine, cite OpenAI et Databricks) ; SDK MCP TypeScript v2 (spec 2026-07-28, paquets `@modelcontextprotocol/server` 2.3, adaptateurs Express/Fastify/Hono, helpers OAuth) ; Node 24 LTS, Node 26 courant ; Bun 1.4.3 ; Tailwind 4.3 ; Base UI 1.0.0-rc.0 ; shadcn/ui supporte Radix, Base UI et React Aria.

## 2. Comparaison pour le cas Leon

| Option | Pour | Contre pour Leon |
|---|---|---|
| **TS full-stack** (Next.js + Hono + Drizzle) | Un seul langage, un seul typage de bout en bout (schéma DB → API → UI → MCP → agent local → extension, tous en TS) ; meilleure couverture par les agents de code ; SDK MCP de référence | Pipeline LLM un peu moins outillé qu'en Python, mais Leon appelle des API, il n'entraîne rien |
| Python (FastAPI + SQLAlchemy) + front Next.js | Écosystème LLM (instructor, pydantic-ai) | Deux langages, deux chaînes d'outils, deux jeux de types pour deux personnes ; le serveur MCP, l'agent local et l'extension restent en TS de toute façon |
| Go / Rust (Axum) | Performance, binaires | Aucun gain pour une app CRUD + files d'attente ; itération plus lente ; Dust n'a mis du Rust que dans le cœur vectoriel, après des années |

Files d'attente : BullMQ (Redis à opérer), pg-boss et Graphile Worker (Postgres seul, pas de service en plus, données en UE par construction), Inngest (Go, SSPL, cloud sans région UE documentée, auto-hébergement sans support), Trigger.dev (Apache-2, auto-hébergeable, mais warm starts et checkpoints réservés au cloud), Temporal (ce que Dust utilise ; Temporal Cloud a Francfort, Irlande, Londres ; lourd pour deux fondateurs au départ). Auth : Clerk (Pro 25 $/mois, SSO 75 $/connexion/mois dès la 2e, add-on B2B 100 $/mois, pas de résidence UE sur la page tarifs), WorkOS (1 M MAU gratuits mais SSO 125 $/connexion/mois), Better Auth (MIT, plugin organisation avec équipes et **rôles dynamiques**, plugin SSO SAML/OIDC + SCIM, et surtout **plugin MCP qui fait de Leon un serveur OAuth 2.1** avec métadonnées RFC 9728 : exactement ce qu'il faut pour que Claude, ChatGPT et Cursor se connectent au MCP de Leon avec les droits de l'utilisateur).

Hébergement UE vérifié : Vercel fra1/cdg1/dub1/lhr1/arn1 (**région par défaut iad1, à changer explicitement**) ; Railway une seule région UE (Amsterdam) ; Fly.io ams/cdg/fra/lhr/arn ; Neon Francfort et Londres (régions Azure dépréciées) ; Supabase Francfort, Paris, Londres, Zurich, Stockholm, Irlande ; Hetzner Falkenstein, Nuremberg, Helsinki ; Scaleway Paris, Amsterdam, Varsovie ; Sentry région UE à Francfort (`de.sentry.io`, mais comptes et journaux d'audit restent aux États-Unis). Le débat « Vercel vs VPS » se résume ainsi : Vercel + Postgres managé coûte zéro ops et reste la norme des startups ; Hetzner + Coolify (63 k étoiles) divise la facture par 5 à 10 mais ajoute de l'ops ; le bon moment pour basculer est quand la facture dépasse quelques centaines d'euros par mois ou qu'un client exige un hébergeur allemand ou français.

## 3. Recommandation ferme

- **Langage** : TypeScript partout, Node 24 LTS en production, pnpm. Bun en option pour tests et scripts ; pas de runtime Bun en prod en 2026.
- **Monorepo** : pnpm workspaces + Turborepo. `apps/web` (Next.js 16, App Router), `apps/api` (Hono : API publique, webhooks des connecteurs, serveur MCP en Streamable HTTP), `apps/worker` (consommateurs pg-boss), `apps/agent` (agent local, CLI), `apps/extension`, `packages/db` (Drizzle), `packages/core` (fiches, faits, droits, résolution d'entités), `packages/connectors`, `packages/ui`. Le web appelle `core` directement en server actions ; Hono expose le même `core` aux clients externes.
- **Framework** : Next.js 16 pour l'interface ; Hono pour tout ce qui doit tourner longtemps ou hors Vercel (webhooks, MCP, API). Pas de tRPC : client typé Hono (`hc`) suffit.
- **ORM** : Drizzle + drizzle-kit, Postgres 17 avec pgvector. Drizzle a dépassé Prisma, n'a aucune dépendance, et son SQL transparent sert bien les agents de code et le RLS. Prisma 8 n'est pas un mauvais choix ; on ne change pas d'ORM en cours de route.
- **Files d'attente** : **pg-boss 12** (Postgres seul : ingestion, synchro, pipeline de tri par LLM, reprises, planification). Passage à Temporal (Cloud Francfort ou auto-hébergé) seulement si les workflows multi-étapes deviennent ingérables, pas avant.
- **Auth** : **Better Auth** avec plugins organization (équipes, rôles dynamiques), sso (SAML/OIDC Google Workspace et Microsoft Entra), mcp (serveur OAuth pour les clients MCP). WorkOS plus tard uniquement si un grand compte exige SCIM géré.
- **UI** : shadcn/ui sur Radix (pas Base UI tant que le 1.0 n'est pas stable et par défaut), Tailwind 4, TanStack Query, react-hook-form + zod, cmdk pour la palette de commandes, Shiki/CodeMirror pour le Markdown brut.
- **Hébergement (phase pilote)** : Next.js sur Vercel région `fra1` ; `api` et `worker` en conteneurs sur Fly.io `fra`/`cdg` (Railway Amsterdam en alternative) ; Postgres sur **Neon Francfort** (branches de base par PR, pratiques avec les agents) ou Supabase Paris si l'on veut un acteur unique ; S3 compatible Scaleway Paris pour les conversations brutes ; Sentry UE + OpenTelemetry + pino, Langfuse auto-hébergé pour tracer les appels LLM. **Phase 2** : Hetzner Falkenstein + Coolify, ou Scaleway Paris quand un client exige du souverain.
- **Connecteurs** : codés maison, un paquet par source avec une interface commune (`authorize`, `backfill(cursor)`, `handleWebhook`, `normalize`). OAuth : pour Google, Better Auth gère la liaison de compte et le rafraîchissement ; pour Notion, Linear, HubSpot, GitHub App, la bibliothèque `arctic` (5,5 M/mois) + une table de jetons chiffrés avec rafraîchissement sous verrou. SDK officiels : @octokit/rest (90 M), googleapis (47 M), @linear/sdk (12 M), @notionhq/client (8,4 M), @hubspot/api-client (6,9 M). Webhooks : vérifier la signature, répondre 200 tout de suite, empiler un job pg-boss. Backfill : jobs paginés avec curseur persistant par connexion (reprise au point exact). Rate limits : limiteur par connexion (Notion 3 req/s, HubSpot 110/10 s) + respect de `Retry-After`. Idempotence : clé (source, id externe, version). **Nango** : licence Elastic 2.0 (interdit de le revendre comme service, pas de l'utiliser), README « auto-hébergement gratuit à fonctions réduites » mais page tarifs « self-hosting réservé à Enterprise » ; cloud 10 connexions gratuites puis 0,29 $/connexion. Il redevient pertinent au connecteur 6 et au-delà (Pipedrive, Attio, monday, Freshdesk), jamais pour les cinq premiers.

## 4. Exotique ou à éviter

Rust/Go pour l'application ; backend Python séparé (deux langues pour deux personnes) ; Effect-TS ; Elysia et tout framework « Bun seulement » ; Deno ; NestJS (B-tier, lourd) ; Base UI avant stabilité ; GraphQL pour sa propre API ; microservices et Kubernetes ; Temporal ou Kafka dès le jour 1 ; Redis uniquement pour une file ; Inngest Cloud (SSPL, UE non documentée) ; Clerk (coût SSO par connexion, résidence UE non affichée) ; Convex/Firebase (verrouillage) ; agrégateur de connecteurs pour les cinq premières sources.

## 5. Non vérifié

Budget WebSearch épuisé : je n'ai pas pu vérifier la stack de YC S26, de Linear (réputé TS/Node/MobX), d'Attio ni de Granola ; Qontext, memory.store et Sentra n'ont pas de dépôt public identifié. Stack Overflow 2026 : seule la page de synthèse était lisible (langages, bases, LLM) ; les frameworks viennent du 2025. State of JS 2025 : chiffres en nombre de répondants pour outils et hébergement, pas en pourcentage. Le chiffre npm de Hono (304 M) est gonflé par les outils qui le dépendent ; son usage réel est bien moindre que Next.js. Prisma 8 : date lue sur le blog du jour ; npm affichait encore `8.0.0-rc.22`. Nango : contradiction README/tarifs sur l'auto-hébergement, à trancher par un mail à Nango. Prix Hetzner et Scaleway non lus (pages dynamiques). Neon sous Databricks : non confirmé sur la page des régions. Licence exacte de Workflow DevKit (Vercel, v5) non lue.
