# Tâches v1 : plan d'implémentation

15 octobre 2026 · Amos (avec Claude) · à relire par David

Met en œuvre la [spec des tâches](../specs/2026-10-15-taches.md). Les **règles de simplicité**, les **contraintes d'environnement des agents** (sandbox, Postgres, Turbopack, `tsx`, journaux, secrets) et le **build de vérification** du [plan du premier jet](2026-10-13-premier-jet.md) (sections « Règles de simplicité » et « Contraintes globales ») s'appliquent tels quels. Exceptions écrites ici : la migration `0007`, les dépendances de C9 et les composants shadcn de T06. Relu par un agent Opus le 15/10 ; ses corrections sont intégrées.

## Méthode

- Branche `amos/taches-v1`, worktree `.claude/worktrees/taches-v1`. **Une tâche = un commit** (fichiers ajoutés un par un, `git status` relu), message en français, pied `Co-Authored-By` du modèle qui a écrit.
- Par tâche : un **implémenteur** ; puis trois relecteurs **en parallèle**, en lecture seule : **validateur** (spec, plan, critères, lance les vérifications), **audit des contrats d'exécution** (skill `auditing-runtime-contracts`), **revue de sécurité** (skill `security-review`) ; puis un **correcteur** pour les défauts réels, qui fait un commit de correction.
- Modèles : Opus pour la planification, la relecture du plan et les droits (T02 et sa revue de sécurité) ; Sonnet pour l'implémentation et les relectures.
- Tâches **séquentielles** dans le même worktree (`pnpm typecheck` et les contrats restent verts entre deux commits) ; seules les relectures tournent en parallèle.
- Le projet n'a ni jsdom ni test en navigateur : ce qui relève du clavier, du glisser-déposer, du retour arrière et du rendu se vérifie à la main par l'orchestrateur (app lancée, captures en clair et en sombre).
- Un besoin de dépendance, de table ou de colonne non prévu ici, ou un défaut hors du périmètre : l'agent s'arrête et le signale.

### C2. Schéma SQL (`0007-taches.sql`, T02)

Motif de `0003-memoire.sql` et `0005-durcissement.sql`. **L'ACL d'une tâche est celle de son projet** (v1 : toutes d'équipe, `[tenant]`). Les clés étrangères ignorent la RLS : le code vérifie par une lecture sous RLS que le parent, le projet et le statut visés sont visibles. Valeurs réservées au jet suivant retirées (« rien au cas où ») ; le jet suivant élargira les `check`.

```sql
-- Projets, tâches, étiquettes et vues portent une ACL (celle d'une tâche = celle de son projet,
-- posée par tasks_guard) ; statuts, liens d'étiquettes, commentaires et journal suivent la
-- visibilité de leur parent.
-- Les clés étrangères ignorent la RLS : le code vérifie la visibilité des lignes visées.

  id uuid primary key default gen_random_uuid(),

  project_id uuid not null,

-- Le compteur n'avance que d'un pas (takeNumber) : remis à zéro ou poussé au maximum, il bloquerait
-- toute création.
create function task_projects_guard() returns trigger language plpgsql as $$
begin
  if new.last_number not in (old.last_number, old.last_number + 1) then
    raise exception 'compteur de numéros modifié' using errcode = '42501';
  end if;
  return new;
end $$;
create trigger task_projects_guard before update of last_number on task_projects
  for each row execute function task_projects_guard();

-- Numéro et ACL d'une tâche viennent de son projet, lu sous la RLS de l'appelant (security invoker).
-- Le numéro est celui que createTask ou un changement de projet vient de prendre au compteur, dans
-- la même transaction ; sans changement de projet, il ne bouge plus.
create function tasks_guard() returns trigger language plpgsql as $$
declare
  project record;
begin
  if tg_op = 'UPDATE' and new.project_id = old.project_id then
    if new.number <> old.number then
      raise exception 'numéro de tâche modifié' using errcode = '42501';
    end if;
    return new;
  end if;
  select acl, last_number into project from task_projects where id = new.project_id;
  if not found then
    raise exception 'projet de la tâche invisible' using errcode = '42501';
  end if;
  if new.number <> project.last_number then
    raise exception 'numéro de tâche hors du compteur' using errcode = '42501';
  end if;
  new.acl := project.acl;
  return new;
end $$;
create trigger tasks_guard before insert or update of project_id, number on tasks
  for each row execute function tasks_guard();

-- Droits au plus juste : pas de suppression de projet, commentaires et journal en ajout seul,
-- mises à jour limitées aux colonnes modifiables (jamais tenant_id, acl, creator_id, origin) ;
-- last_number et number restent gardés par les déclencheurs ci-dessus.
grant select, insert on task_projects, task_statuses, tasks, task_labels, task_views,
  task_label_links, task_comments, task_events to leon_app;
grant update (key, name, last_number) on task_projects to leon_app;
grant update (label, color, category, position) on task_statuses to leon_app;
grant update (project_id, number, status_id, parent_id, title, description_md, priority, assignee_id,
  due_date, position, status_changed_at, completed_at, updated_at) on tasks to leon_app;
grant update (name, color) on task_labels to leon_app;
grant update (name, config, is_team_default, updated_at) on task_views to leon_app;
grant delete on task_statuses, tasks, task_labels, task_label_links, task_views to leon_app;
```
