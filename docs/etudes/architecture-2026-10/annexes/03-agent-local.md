# R3 : l'agent local de Leon (12 octobre 2026)

## 1. Formats et emplacements vérifiés

**Claude Code** (vérifié sur cette machine, Claude Code 2.1.280, et doc officielle). Chemin : `~/.claude/projects/<cwd encodé, « / » remplacé par « - »>/<uuid-session>.jsonl`, mode 0600, écrit en ajout pur (append-only). À côté, un dossier `<uuid-session>/tool-results/` (gros résultats d'outils, PDF téléchargés) et `~/.claude/history.jsonl`. Windows : `%USERPROFILE%\.claude` ; `CLAUDE_CONFIG_DIR` déplace tout. Chaque ligne est un objet JSON avec un champ `type`. Lignes de conversation : `user` et `assistant`, portant `uuid`, `parentUuid` (chaînage, donc branches), `sessionId`, `timestamp`, `cwd`, `gitBranch`, `version`, `isSidechain` (sous-agent) et `message.content`, soit une chaîne, soit une liste de blocs `text`, `thinking`, `tool_use` (`id`, `name`, `input`) et `tool_result` (`tool_use_id`, `content`) ; les lignes `user` qui portent un `tool_result` ont aussi un `toolUseResult` dupliqué. Autres lignes, à ignorer : `system`, `attachment` (sorties de hooks), `file-history-snapshot/delta`, et des métadonnées (`ai-title`, `last-prompt`, `pr-link`, `mode`…). Mesure sur 12,4 Mo de sessions de ce projet : texte utile 3,8 %, `tool_result` 37 %, entrées d'outils 7 %, lignes hors conversation 29 %. Rétention : 30 jours par défaut (`cleanupPeriodDays`), les sessions lancées depuis Claude Desktop/Cowork sont exemptées ([data-usage](https://code.claude.com/docs/en/data-usage)). Hooks : `SessionStart` reçoit `session_id`, `transcript_path`, `cwd`, `source` ; il injecte du contexte via stdout ou `hookSpecificOutput.additionalContext` ([hooks](https://code.claude.com/docs/en/hooks)).

**Codex CLI** (vérifié dans le code source, pas sur disque : Codex n'est pas installé ici). Chemin : `~/.codex/sessions/YYYY/MM/DD/rollout-YYYY-MM-DDThh-mm-ss-<uuid>.jsonl`, plus `archived_sessions/` ([list.rs](https://github.com/openai/codex/blob/main/codex-rs/rollout/src/list.rs)). Chaque ligne est un `RolloutLine` : `timestamp`, `ordinal`, puis l'item étiqueté par `type` : `session_meta` (`id`, `session_id`, `timestamp`, `cwd`, `cli_version`, `instructions`, `git`, et désormais `creator_user_id`/`creator_account_id`), `response_item` (`Message` avec `role`/`content`, `FunctionCall`, `FunctionCallOutput`, `Reasoning`, `LocalShellCall`, `CustomToolCall`, `WebSearchCall`), `event_msg`, `compacted`, `turn_context`, `token_usage_record` ([history/lib.rs](https://github.com/openai/codex/blob/main/codex-rs/history/src/lib.rs)). Deux pièges récents : les fichiers froids sont compressés en arrière-plan en `.jsonl.zst` ([compression.rs](https://github.com/openai/codex/blob/main/codex-rs/rollout/src/compression.rs)), et un index SQLite `state_db` apparaît. Hooks : `~/.codex/hooks.json`, mêmes événements que Claude Code (`SessionStart`, `UserPromptSubmit`…), même champ `additionalContext`, plafond ~2 500 jetons ([doc hooks](https://learn.chatgpt.com/docs/hooks)).

**Cursor** (vérifié sur cette machine, 104 Mo). macOS : `~/Library/Application Support/Cursor/User/globalStorage/state.vscdb` (Windows `%APPDATA%\Cursor\User\globalStorage`, Linux `~/.config/Cursor/User/globalStorage`, par convention VS Code, non vérifié). SQLite, `journal_mode=delete`, deux tables clé/valeur : `ItemTable` et `cursorDiskKV`. Dans `cursorDiskKV` : `composerData:<id>` (une conversation : `name`, `createdAt`, `lastUpdatedAt`, `fullConversationHeadersOnly` = liste ordonnée de `bubbleId`), `bubbleId:<composerId>:<bubbleId>` (un message : `type` 1 = humain, 2 = assistant, `text`, `toolFormerData`, `toolResults`, `codeBlocks`, `allThinkingBlocks`…), `checkpointId:` (instantanés de fichiers : 77 Mo sur 104 ici, c'est ce qui gonfle) et `codeBlockDiff:`. Non documenté, aucun export officiel. Cursor a en revanche des hooks (`~/.cursor/hooks.json`) : `beforeSubmitPrompt` reçoit `prompt`, `afterAgentResponse` reçoit `text`, `sessionStart` accepte `additional_context` ([doc](https://cursor.com/docs/agent/hooks)).

**Autres.** Gemini CLI : `~/.gemini/tmp/<hash projet>/chats/` ([doc](https://github.com/google-gemini/gemini-cli/blob/main/docs/cli/session-management.md)). Windsurf et Claude Desktop : non vérifiés.

**Détection des changements.** Claude Code et Codex ajoutent des lignes : il suffit d'un watch de répertoire (FSEvents / inotify / ReadDirectoryChangesW) et d'un curseur « octets lus par fichier » conservé localement. Cursor réécrit une base SQLite : on surveille le mtime du fichier, puis on relit uniquement les `composerData` dont `lastUpdatedAt` a changé, et leurs bulles.

## 2. Comparaison des technologies

| Option | Pour | Contre |
|---|---|---|
| **Rust** (binaire unique) | 5–15 Mo, 10–30 Mo RAM, pas de runtime ; `notify` couvre les trois OS ([docs](https://docs.rs/notify)) ; `keyring` 4 couvre Keychain, Credential Manager, Secret Service ([docs](https://docs.rs/keyring)) ; `rusqlite` lit Cursor ; Tauri 2 réutilise le même code si on veut une barre de menu ou une fenêtre | Compilation plus lente, courbe d'apprentissage, mais bien servi par les agents IA de code |
| **Go** (Tailscale, Datadog) | Très simple, cross-compile trivial, services système éprouvés ([Tailscale](https://github.com/tailscale/tailscale), [Datadog](https://github.com/DataDog/datadog-agent)) | Pas de chemin natif vers une UI ; Tailscale et Datadog ajoutent des enveloppes Swift/C# propriétaires |
| **Swift / C# natifs** | Intégration OS parfaite | Deux bases de code, deux fondateurs : non |
| **Node packagé** (`bun build --compile`) | Même langage que le serveur et l'extension | 50–90 Mo, entitlements JIT à signer sur macOS, mémoire élevée pour un démon permanent ([doc](https://bun.sh/docs/bundler/executables)) |
| **Electron** | UI riche | 150 Mo et 100+ Mo RAM au repos pour un processus sans interface : disproportionné |

Les produits comparables confirment la tendance : Dropbox a réécrit son moteur de synchronisation en Rust pour la justesse et le multiplateforme ([Dropbox](https://dropbox.tech/infrastructure/rewriting-the-heart-of-our-sync-engine)), Warp est en Rust ([Warp](https://www.warp.dev/blog/how-warp-works)), Pieces fait tourner un service local de fond séparé de son application ([PiecesOS](https://docs.pieces.app/products/core-dependencies/pieces-os)), Tailscale sépare démon et enveloppe graphique.

## 3. Recommandation ferme

- **Langage : Rust, un seul binaire `leon`** avec sous-commandes : `leon daemon` (service), `leon status | pause | resume | preview | exclude | hooks install | native-host | update`. Pas d'interface graphique au départ ; si une icône de barre de menu devient nécessaire, Tauri 2 sur la même base de code. Logs lisibles dans `~/.leon/logs/`, code publié en lisibilité (auditable, c'est un argument de vente).
- **Architecture interne** : trois lecteurs (Claude Code, Codex, Cursor) derrière un trait `Source` qui produit des `Turn { source, session_id, project, ts, role, text, tool_names }` ; le filtre jette `tool_result`, `thinking`, `attachment`, entrées d'outils (on garde le nom de l'outil et le chemin, pas le contenu) ; file d'attente locale SQLite, envoi par lots, idempotent (`uuid` de ligne / `bubbleId`). Pour Cursor, **installer aussi les hooks** : `beforeSubmitPrompt` et `afterAgentResponse` donnent le texte proprement ; la lecture de `state.vscdb` ne sert qu'au rattrapage de l'historique.
- **Distribution** : macOS `.pkg` signé Developer ID + notarisé + agrafé, qui pose le binaire et un LaunchAgent dans `~/Library/LaunchAgents` (SMAppService exige un bundle .app, inutile pour une CLI) ([Apple](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution)) ; Windows MSI signé via Azure Artifact Signing (ex-Trusted Signing, [doc](https://learn.microsoft.com/en-us/azure/artifact-signing/overview)) + tâche planifiée à l'ouverture de session ; Linux `.deb/.rpm` + `systemd --user`. Pour les devs : Homebrew tap et `curl | sh`.
- **Mise à jour** : auto-update intégré au binaire, manifeste JSON signé minisign (le schéma de l'updater Tauri : `version`, `platforms[os-arch].url/signature`, [doc](https://v2.tauri.app/plugin/updater/)), vérification horaire, déploiement progressif, `leon update` manuel. Sparkle écarté (bundle .app seulement, [doc](https://sparkle-project.org/documentation/)). La clé privée dans un HSM/KMS dès le jour 1 : la perdre bloque toute mise à jour.
- **Sécurité** : enrôlement par flux OAuth « device » dans le navigateur ; jeton dans Keychain / Credential Manager / Secret Service via `keyring`, repli fichier 0600 sur Linux sans bureau ; TLS 1.3 (rustls) avec épinglage de l'autorité ; signature stable du binaire pour éviter les invites Keychain à chaque mise à jour. Consentement explicite à l'installation, `leon preview` montre exactement ce qui part, exclusions par projet (`.leonignore` ou `leon exclude <chemin>`), redaction locale des motifs de secrets (clés API, jetons) avant envoi, et rappel : la conversation brute reste privée à l'auteur côté serveur.
- **Pont extension** : hôte de native messaging = le même binaire en mode `leon native-host`, déclaré dans `~/Library/Application Support/Google/Chrome/NativeMessagingHosts/`, la clé de registre `HKCU` sur Windows, `~/.config/google-chrome/NativeMessagingHosts/` sur Linux ; protocole stdio à préfixe de longueur 4 octets, 1 Mo max entrant ([Chrome](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging)). L'hôte est lancé par connexion : il relaie vers le démon par socket Unix / named pipe.
- **Hooks** : `leon hooks install` écrit `SessionStart` dans `~/.claude/settings.json`, `~/.codex/hooks.json`, `~/.cursor/hooks.json`, pointant sur `leon briefing --host <x>`, qui lit un briefing mis en cache par le démon (réponse instantanée, pas d'appel réseau bloquant au démarrage), sous 2 500 jetons pour Codex.

## 4. Risques spécifiques

- **Changements de format** : trois éditeurs, zéro contrat. Parsers tolérants (types inconnus ignorés, champs optionnels), fixtures de non-régression par version (`version` Claude Code, `cli_version` Codex, `_v` Cursor), et remontée des erreurs de parsing au serveur pour détecter une rupture en quelques heures. Codex vient de passer à la compression zstd et à un index SQLite : lire les deux représentations.
- **Cursor 30 Go** : jamais de `VACUUM` ni d'écriture ; ouverture `?mode=ro&immutable=1` interdit (risque de lecture incohérente pendant une écriture) ; préférer `mode=ro` avec lecture incrémentale par `lastUpdatedAt`, et pousser les utilisateurs vers les hooks. Les clés `checkpointId:` ne sont jamais lues.
- **Permissions macOS** : `~/.claude`, `~/.codex` et `~/Library/Application Support/Cursor` ne sont pas protégés par TCC (à confirmer sur un Mac neuf) ; pas de Full Disk Access à demander. Gatekeeper exige notarisation ; un binaire resigné différemment déclenche des invites Keychain.
- **Linux** : limite `inotify` sur les grands arbres, pas de Secret Service en SSH.
- **Vie privée** : Codex enregistre désormais l'identifiant de compte ChatGPT ; ne pas le transmettre.
