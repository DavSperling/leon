# Tâches v1 : spec

15 octobre 2026 · Amos (avec Claude) · à relire par David

S'appuie sur l'[étude des tâches](../etudes/taches-2026-10/README.md) (PR #12), sur l'analyse de 54 captures de Linear et de Notion et sur la structure de leurs espaces lue par leurs MCP (lecture seule). La [spec du premier jet](2026-10-13-premier-jet.md) et ses règles de code s'appliquent ; pour le style, c'est le code de la PR #11 qui fait foi (Inter, accent indigo, panneau blanc sur fond gris), pas la [spec de design](2026-10-13-design.md) du 13/10.

## Le but

Un gestionnaire de tâches dans Leon, **réglable comme Linear et comme un éditeur de code** : chacun choisit sa disposition, son regroupement, ses colonnes, son thème, et tout se fait au clavier. Une tâche est une page (propriétés en haut, description riche, sous-tâches, commentaires, historique), à la manière de Notion.

Ce jet livre la partie manuelle et la partie agents : on crée et on suit les tâches dans l'interface, et Claude Code les crée, les lit et les démarre par MCP. L'alimentation automatique depuis les conversations, GitHub et le briefing viennent au jet suivant (lots 4 à 7 de l'étude).

**C'est réussi si** Amos et David gèrent le développement de Leon dans Leon pendant une semaine sans retourner sur Linear ou Notion, et si Claude Code démarre une tâche (`task_start`) et en crée de nouvelles sans aide.

## Ce qu'on a retenu des captures et des MCP

- **Linear** (référence principale) : listes denses groupées par statut, groupes repliables avec compteur et « + » ; identifiant court `LEO-12` partout ; options d'affichage (liste ou tableau, regroupement, tri, propriétés affichées) ; vues enregistrées en onglets ; filtres par critères ajoutés un à un ; même trio de contrôles à droite de chaque vue (filtre, affichage) ; icônes de statut et de priorité ; raccourcis affichés dans les menus et les infobulles ; « N tâches masquées par l'affichage » ; « + » dans chaque colonne du tableau.
- **Notion** : statuts **rangés par catégorie** et vues qui filtrent sur la catégorie (renommer un statut ne casse rien) ; tâche = page avec propriétés puis corps en blocs ; commande `/` ; vues « tableau » et « mes tâches » ; un seul panneau qui règle toute la vue.
- **Leurs MCP** : un outil qui lit le schéma avant d'écrire, un `update` qui prend un patch de propriétés plutôt que dix outils, la lecture séparée de l'écriture, rien de destructeur par défaut.
- **Repris en plus** : sélection multiple (case au survol, X) et actions groupées ; panneau de répartition à droite de la liste (nombre de tâches par assigné, étiquette, priorité, projet, chaque ligne servant de filtre) ; « Mes tâches » en onglets (Assignées, Créées, Activité) ; « Définir comme affichage par défaut de l'équipe » ; propriété « dans ce statut depuis » ; parent affiché en fil d'Ariane sur les lignes et les cartes ; aide des raccourcis et états vides qui enseignent la touche.
- **Écartés pour ce jet** : cycles, initiatives, santé des projets, boîte de réception, « Pulse », agent conversationnel, chronologie, calendrier, formules, automatisations, couleurs conditionnelles, panneau latéral d'aperçu (la tâche s'ouvre en page entière).

## Modèle

Un **projet** porte une clé (`LEO`), ses statuts et ses tâches ; c'est l'équivalent d'une équipe Linear. Un projet par défaut est créé à la première visite de `/taches` : nom de l'organisation, clé tirée de ce nom (trois premières lettres sans accent, en majuscules, `TCH` si rien ne convient), modifiable dans les réglages.

| Objet | Champs |
|---|---|
| Projet | clé, nom, prochain numéro, visibilité |
| Statut | libellé, couleur, ordre, **catégorie** : `backlog`, `todo`, `started`, `done`, `canceled` (la catégorie `triage` viendra avec l'alimentation automatique) |
| Tâche | `LEO-12`, titre, description (Markdown), statut, priorité (`none`, `urgent`, `high`, `medium`, `low`), assigné, échéance, parent (sous-tâche), étiquettes, position, origine (`ui`, `mcp`, et plus tard `cli`, `pipeline`, `github`), dates de création, de mise à jour, de changement de statut et de fin |
| Étiquette | nom, couleur ; communes à l'organisation |
| Commentaire | auteur, texte Markdown |
| Événement | qui (personne ou agent, avec le nom du client MCP), quoi (création, statut, priorité, assigné, étiquettes, échéance, titre, parent, commentaire), avant et après |
| Vue enregistrée | nom, réglages d'affichage et filtres, personnelle ou d'équipe |

Statuts par défaut, ceux de Linear : Backlog (`backlog`), À faire (`todo`), En cours (`started`), En revue (`started`), Terminé (`done`), Annulé (`canceled`), Doublon (`canceled`). Une nouvelle tâche prend le premier statut `backlog` (à défaut `todo`) ; une sous-tâche hérite du projet et de la priorité de son parent, pas des étiquettes. Étiquettes par défaut : Bug, Fonctionnalité, Amélioration.

**Droits** : même règle que la mémoire. Projets, tâches et étiquettes ont une ACL ; en v1 elles sont toutes d'équipe (`[tenant]`). Les vues enregistrées sont personnelles (`[moi]`) ou d'équipe. Commentaires, événements et liens d'étiquettes n'ont pas d'ACL propre : ils sont visibles si leur tâche l'est. Le journal des événements est en ajout seul.

## Réglages d'une vue

Un même objet décrit l'affichage, dans l'URL (partageable) comme dans une vue enregistrée :

| Réglage | Valeurs | Défaut |
|---|---|---|
| Disposition | liste, tableau | liste |
| Regrouper par | statut, priorité, assigné, projet, étiquette, aucun | statut |
| Trier par | manuel, priorité, échéance, création, mise à jour | priorité |
| Propriétés affichées | identifiant, statut, priorité, étiquettes, projet, assigné, échéance, sous-tâches, parent, dans ce statut depuis, création, mise à jour | toutes sauf les trois dernières |
| Sous-tâches | visibles ou non dans la liste | visibles |
| Groupes vides | visibles ou non | masqués |
| Panneau de répartition | ouvert ou fermé | fermé |
| Filtres | statut (catégories), priorité, assigné (`moi`, personne, aucun), étiquette, projet, échéance (en retard, cette semaine, aucune), texte | tâches ni terminées ni annulées |

Les paramètres d'URL sont en français et lisibles : `/taches?disposition=tableau&groupe=priorite&assigne=moi`. Un paramètre absent prend le défaut (celui de l'équipe s'il existe). Le filtre de projet porte l'identifiant interne du projet, pour qu'une clé renommée ne casse pas les vues. Une vue enregistrée s'ouvre par `/taches?vue=<id>`, et toute modification affiche « Enregistrer » ou « Réinitialiser ».

Le menu **Affichage** se termine par « Réinitialiser » et « Définir par défaut pour l'équipe » : ce défaut d'équipe (une vue d'équipe marquée par défaut) remplace les défauts ci-dessus pour tout le monde.

## Écrans

### Ossature

- La barre latérale gagne **Tâches** (icône `SquareCheck`), entre Briefing et À vérifier.
- La colonne « Mémoire partagée » (arbre des fiches) reste sur les pages de la mémoire. Sur `/taches`, elle est remplacée par la **navigation des tâches** : Mes tâches, Toutes les tâches, puis les projets, puis les vues enregistrées (personnelles, puis d'équipe), avec un compteur de tâches ouvertes.
- **Thème** clair, sombre ou système, dans le menu du compte et dans ⌘K. Mémorisé par cookie, appliqué côté serveur (aucun flash). Défaut : clair (le rendu actuel ne change pas).
- **Barre latérale repliable** (⌘B), mémorisée par cookie.

### Liste (`/taches`)

En-tête : fil d'Ariane (`Tâches / Toutes`), onglets des vues enregistrées du contexte, puis à droite **Filtrer** (F), **Affichage**, **Nouvelle tâche** (C). Sous l'en-tête, les filtres actifs en pastilles retirables.

- Groupes repliables : icône, nom, compteur, « + » qui ouvre la création avec ce groupe prérempli.
- Ligne de 36 px : priorité, identifiant (mono), icône de statut, titre (le code entre accents graves est rendu en mono), étiquettes (point coloré + nom), sous-tâches (`2/5`), projet, assigné (initiales), échéance (en rouge si dépassée). Un clic sur une icône ouvre son sélecteur sur place ; un clic sur la ligne ouvre la tâche.
- Pied : « N tâches masquées par les filtres » avec un lien pour les retirer.
- États vides : une phrase et l'action (« Aucune tâche. Créer une tâche (C) »).
- **Sélection multiple** : une case apparaît au survol (et X sur la ligne sélectionnée) ; Maj+clic étend la sélection. Une barre flottante en bas donne le nombre et les actions groupées : statut, priorité, assigné, étiquettes, échéance, supprimer. Échap vide la sélection.
- **Panneau de répartition** (bouton à droite de l'en-tête) : onglets Assignés, Étiquettes, Priorité, Projets, avec le nombre de tâches par valeur ; un clic sur une valeur filtre la liste.

**Mes tâches**, en onglets : Assignées (`/taches?assigne=moi`), Créées (`?createur=moi`), Activité (`?onglet=activite`) : les tâches qui me sont assignées, celles que j'ai créées, et le fil des derniers événements sur les tâches qui me concernent.

### Tableau

Mêmes données, en colonnes selon le regroupement. Cartes : identifiant, titre sur deux lignes, statut, priorité, étiquettes, assigné, échéance. On **glisse une carte** d'une colonne à l'autre (change le statut, la priorité ou l'assigné selon le regroupement) et, en tri manuel, on la range dans sa colonne. « + » en tête de chaque colonne. Le glisser-déposer a un équivalent clavier (sélecteurs S, P, A).

### Création rapide

Dialogue (C ou « + ») : titre, description riche, puis une rangée de pastilles (projet, statut, priorité, assigné, étiquettes, échéance, parent). ⌘Entrée crée ; « Créer et continuer » garde le dialogue ouvert.

### Page d'une tâche (`/taches/LEO-12`)

Deux colonnes, comme Linear :
- **Gauche** : fil d'Ariane (`LEO / LEO-12`, parent s'il y en a), titre modifiable sur place, description en éditeur riche, sous-tâches (liste compacte + « Ajouter une sous-tâche »), puis **Activité** : événements et commentaires mêlés dans l'ordre, et la zone de commentaire (⌘Entrée envoie).
- **Droite** (280 px) : statut, priorité, assigné, étiquettes, projet, échéance, parent ; puis « Copier l'identifiant », « Copier le nom de branche » (`amos/leo-12-titre-court`, préfixé par le prénom de celui qui copie, comme nos branches), « Copier pour un agent » (la tâche en Markdown, prête à coller dans Claude Code, comme le « copier pour un LLM » de Linear), « Supprimer » (avec confirmation).

### Éditeur riche

Description et commentaires utilisent le même éditeur, stocké en Markdown. Raccourcis Markdown à la frappe (`#`, `-`, `1.`, `[]`, ` ``` `, `>`), et menu `/` : titres 1 à 3, liste, liste numérotée, cases à cocher, bloc de code, citation, séparateur. Enregistrement automatique (après une pause de frappe et à la sortie du champ), avec un indicateur discret « Enregistré ».

### Réglages des tâches (`/taches/reglages`)

Projets (nom, clé), statuts du projet (libellé, couleur, catégorie, ordre ; supprimer un statut demande où déplacer ses tâches), étiquettes (nom, couleur). Lignes « libellé, description, contrôle », comme les réglages de Linear.

### Sélecteurs

Un seul motif partout (ligne, carte, page, création) : menu flottant avec champ de recherche, options avec icône et raccourci, navigation aux flèches. Statut, priorité, assigné (membres de l'organisation, « Moi » en premier, « Aucun »), étiquettes (cases multiples, « Créer l'étiquette … »), échéance (Aujourd'hui, Demain, Vendredi, Semaine prochaine, une date, Aucune), projet, parent (recherche par identifiant ou titre).

## Clavier

Les raccourcis à une lettre comparent `event.key` (sûr en AZERTY) et sont inactifs dès qu'un champ ou l'éditeur a le focus.

| Touche | Action |
|---|---|
| ⌘K | palette : aller à `LEO-12`, créer une tâche, changer le thème, ouvrir une vue, actions sur la tâche courante |
| C | nouvelle tâche |
| J / K ou ↓ / ↑ | ligne suivante, précédente (liste) |
| Entrée | ouvrir la tâche sélectionnée |
| X | ajouter ou retirer la ligne de la sélection multiple |
| S, P, A, L, D | statut, priorité, assigné, étiquettes, échéance de la tâche sélectionnée ou ouverte |
| F | ajouter un filtre |
| G puis T | aller aux tâches ; G puis M : mes tâches |
| ⌘B | replier la barre latérale |
| Échap | fermer, ou revenir à la liste depuis une tâche |
| ? | aide des raccourcis |

## Agents : outils MCP

Ajoutés au serveur MCP existant, sous les droits de l'utilisateur du jeton :

| Outil | Rôle |
|---|---|
| `task_list` | lister avec filtres (projet, catégorie de statut, `assigne: "moi"`, étiquette, texte, limite) ; renvoie identifiant, titre, statut, priorité, assigné, échéance |
| `task_get` | une tâche en Markdown : propriétés, description, sous-tâches, derniers commentaires ; plus les statuts et étiquettes disponibles (le schéma avant d'écrire) |
| `task_create` | titre, description, projet, priorité, statut, assigné, étiquettes, échéance, parent |
| `task_update` | un patch des mêmes champs sur `LEO-12` |
| `task_comment` | ajouter un commentaire |
| `task_start` | m'assigne la tâche, la passe au premier statut « en cours » et renvoie le nom de branche |

Repris des outils de Linear : on désigne tout **par son nom** (`moi`, l'e-mail d'un membre, le libellé ou la catégorie d'un statut, le nom d'une étiquette, la clé du projet), jamais par un identifiant interne ; les étiquettes s'ajoutent et se retirent (`etiquettes_ajout`, `etiquettes_retrait`) sans écraser les autres ; une erreur dit quoi corriger (« Statut inconnu : En test. Statuts : Backlog, À faire, … »). Chaque action d'agent écrit un événement avec l'origine `mcp` et le nom du client. Aucun outil ne supprime : un agent annule ou marque en doublon. Les consignes du serveur MCP mentionnent les tâches.

## Principes de code

Ceux du [plan du premier jet](../plans/2026-10-13-premier-jet.md) : monolithe, pas de couche service, fonctions courtes, zod aux frontières, les pages n'importent jamais la base. Le code serveur vit dans `src/server/tasks/` ; les modules purs partagés avec l'interface (réglages de vue, identifiants, positions) dans `src/lib/tasks/`.

Code repris de Kaneo (MIT) : idées et algorithmes du tableau et de l'éditeur, avec leur mention dans `docs/licences-tiers.md`. Jamais de code de Plane ou d'un autre projet AGPL.

Nouvelles dépendances, toutes MIT : `@dnd-kit/core`, `@dnd-kit/sortable`, `@dnd-kit/utilities` (tableau), et les paquets libres de TipTap 3 (éditeur). Les composants shadcn manquants (popover, tooltip, checkbox…) s'ajoutent par le CLI shadcn, sans dépendance npm nouvelle. Pas de bibliothèque de dates, de thème ni d'état global.

## Hors de ce jet

Alimentation automatique depuis les conversations, avec la boîte « À trier » de Linear (accepter, refuser, doublon, reporter) et la distinction assigné / délégué (l'agent qui contribue au nom d'un humain), GitHub, briefing, CLI et API HTTP des tâches (jet suivant) ; relations « bloque » et « liée » ; point d'accès MCP en lecture seule ; création par URL préremplie ; parent fermé quand ses sous-tâches le sont ; lien tâche ↔ fiche et mention `@fiche` ; temps réel et co-édition ; cycles, jalons, estimations ; panneau latéral d'aperçu ; raccourcis configurables ; pièces jointes ; boîte de réception et notifications.

## Tests

- Base (`*.db.test.ts`, scénario Paul / Marie / Zoé) : numérotation sans trou ni doublon sous concurrence ; droits (Zoé, d'une autre organisation, ne voit rien ; une vue personnelle n'est visible que de son auteur) ; journal en ajout seul ; changement de statut qui pose ou retire la date de fin ; suppression d'un statut avec déplacement des tâches.
- Purs (`*.test.ts`) : lecture et écriture des réglages de vue depuis l'URL, identifiants et noms de branche, positions du tri manuel, regroupement.
- MCP : chaque outil sur la base de test.
- Contrats existants mis à jour (liens des pages, imports de l'interface) ; build de vérification ; parcours à la main dans les deux thèmes.
