## 2. Static checks that will bite a restyle

### biome.json (`pnpm lint` fails on any ERROR; warnings are tolerated)
- Scope: everything except `docs/etudes`, `prototypes`, `extension/.output`, `extension/.wxt`, `.next`, `pnpm-lock.yaml`. `src/components/ui/**` has the linter off, but that folder does not exist (the real UI kit is `src/components/verre/ui/`, which IS linted).
- Formatter: 2 spaces, line width 100, single quotes, semicolons always. Applies to .ts/.tsx, .css, .json (so `messages/*.json` must be formatted too) and .html.
- Linter: `preset: recommended` plus domains `next: recommended` and `react: recommended`. In practice:
  - a11y: `useButtonType` (every `<button>` needs `type=`), `noSvgWithoutTitle` (an inline `<svg>` needs `<title>` or `aria-hidden`/role), `useKeyWithClickEvents`, `noStaticElementInteractions`, `useSemanticElements`, `noLabelWithoutControl`, `useAnchorContent`, `useValidAnchor`, `noAriaHiddenOnFocusable`. The existing code has `biome-ignore` for 9 of them; a new component that puts `onClick` on a `<div>` will fail.
  - react: `useExhaustiveDependencies` (7 ignores exist), `noArrayIndexKey` (14 ignores), `noChildrenProp` (6, all in tests), `useJsxKeyInIterable`.
  - next: `performance/noImgElement` (a plain `<img>` is an error; 4 ignores exist, e.g. the tool logos in `/public/logos`), `noHeadElement`, `noNextAsyncClientComponent`.
  - css: `noDescendingSpecificity` is ACTIVE on .css and .html (the 3 warnings in docs/specs show it). A new `globals.css` with a base selector after a more specific one will warn (warning only, not error). Also `noDuplicateProperties`, `noUnknownProperty`/`noUnknownFunction` (Tailwind 4 `@theme`, `@utility` are allowed through `css.parser.tailwindDirectives: true`).
  - style/correctness: `useTemplate` (string concat), `noUnusedVariables`, `noUnusedImports`.
  - assist `organizeImports: on`: `biome check` reports unsorted imports as an error. Always finish with `pnpm format`.
- The prototype folder `prototypes/` is excluded from lint and format, so the static HTML never fails the check.

### Typecheck (`tsconfig.json`)
`strict`, `noUncheckedIndexedAccess`, `verbatimModuleSyntax` (a type-only import must say `import type`/`type X`), `isolatedModules`. Message keys are typed from `messages/fr.json` (`src/i18n/request.ts` lines 13-16: `declare module 'next-intl' { interface AppConfig { Messages: typeof fr } }`): `t('namespace.key')` with a key absent from fr.json is a TYPE ERROR, `t('key', { param })` with a wrong parameter name is a type error. English is NOT type-checked (see 4).

## 4. i18n: how en and fr are kept in step, what a missing key does

Mechanism (`src/i18n/request.ts`):

## 8. Risks

1. Hidden coupling by path: five tests mock or import components by exact path (`@/components/verre/shell`, `.../onboarding/{about,tools,teammates,done}-step`, `.../auth/{auth-form,other-sign-in}`, `.../connexions/tool-dialog`, `.../ui/{copy,pill,button}`, `.../reglages/{assistants,computers,tokens,settings-tabs}`). If the builders reorganise `src/components/verre/` into a new folder name, 20+ test files need path edits. Recommendation: keep the folder `src/components/verre/` and the file names, restyle in place; rename later in one mechanical commit.
2. `ui-imports.test.ts` and `page-links.test.ts` scan the whole tree: one builder's mistake breaks everyone's run. Each builder should run the 15-second command (section 5) before handing over.
3. Typecheck does not protect English: an English key typo shows `namespace.key` on screen with every check green except the two i18n tests. Always run them after message edits.
4. The shared local database `leon_refonte` is touched by one dev server only; two builders running `next dev` on it at the same time double the workers and may clobber vectors and queue jobs. Use one server on 3040.
5. `OPENROUTER_API_KEY` is real and the embeddings model is voyage-4: indexing documents and asking questions spend (very little) real money. Do not bulk-load large files.
6. Biome and tsc are fast, but `pnpm build` was not run by me (it needs the Sentry plugin and network for fonts); CI runs it with dummy env. A restyle that adds a font package or a CSS import can fail only at build: run `pnpm build` once at the end of each major slice with the dummy variables from `.github/workflows/tests.yml`.
7. Connections in `error` state keep calling nothing (worker skips unreadable ones) but the Notion row would flip to error within minutes of boot (due sync with an unreadable key); push `next_sync_at` away (step 5) before demoing.
8. Test count in the brief (358) differs from the repo today (370: 267 unit + 103 db); no component test uses a DOM, so "green" says little about visuals: pair the checks with a screenshot pass at 1512 x 771.
